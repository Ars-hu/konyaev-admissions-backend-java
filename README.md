## 1. Описание предметной области и решаемые задачи

Приёмная кампания колледжа ежегодно сопровождается массовым наплывом абитуриентов для подачи оригиналов документов об образовании. Без электронной системы это приводило к «живым» очередям, перегрузке приёмной комиссии и конфликтам.

**Данный бэкенд решает задачи:**
- Предоставление абитуриентам онлайн-записи на фиксированные 10-минутные слоты (`09:00` — `15:00`).
- Защита от перегрузки: на каждый слот установлен лимит вместимости (по умолчанию 3 человека).
- Правило заблаговременной записи (минимум за 24 часа), исключающее внезапный наплыв.
- Поддержка суточных лимитов и блокировки нерабочих/выходных дней.
- Автоматическое архивирование просроченных заявлений каждые 5 минут фоновым планировщиком.
- Выгрузка официальных списков абитуриентов в Excel (`.xlsx`) через Apache POI.

## 2. Роли пользователей

В системе предусмотрено **2 роли** с разграничением прав на уровне Spring Security:

| Роль | Права доступа |
| :--- | :--- |
| **Абитуриент** (`ROLE_APPLICANT` / Публичный доступ) | Просмотр открытых месяцев, доступности дат в календаре, свободных слотов и подача заявления на приём. |
| **Администратор** (`ROLE_ADMIN`) | Вход по JWT, просмотр реестра заявлений (пагинация, поиск, сортировка), смена статусов (`pending`, `confirmed`, `rejected`), удаление заявлений, экспорт в Excel, настройка слотов, блокировка дат, суточные лимиты, просмотр архива. |

## 4. Структура базы данных (PostgreSQL)

База данных содержит **8 взаимосвязанных таблиц**:

1. **`admin`** — учётные записи администраторов (логин, BCrypt-хеш пароля, роль `ROLE_ADMIN`).
2. **`application`** — активные заявления абитуриентов (ФИО, телефон, email, дата, время, статус, дата подачи).
3. **`archived_application`** — архив заявлений после наступления времени приёма.
4. **`slot_config`** — настройки вместимости и блокировки отдельных временных слотов.
5. **`blocked_date`** — заблокированные даты (праздники, неприёмные дни).
6. **`opened_date`** — выходные дни, открытые для приёма.
7. **`allowed_month`** — разрешённые месяцы записи (год, месяц 1-12).
8. **`daily_limit`** — дневные лимиты количества заявлений.
9. **`site_settings`** — параметры системы (`advance_hours = 24`).

## 5. Безопасность и надёжность

- **Абсолютная защита от 500 ошибок:** В `GlobalExceptionHandler` перехвачены все возможные исключения (некорректный JSON, передача букв вместо ID, переполнение чисел, выход за границы диапазонов, ошибки формата дат). Любой некорректный запрос возвращает статус **400 Bad Request** с понятным описанием, сервер никогда не падает с 500 ошибкой.
- **Хеширование паролей:** Пароль администратора хешируется алгоритмом BCrypt (cost factor 10).
- **Stateless JWT:** Авторизация по протоколу Bearer JWT со сроком жизни 24 часа. Секретный ключ и пароли задаются через переменные окружения.
- **Защита от дубликатов:** Проверка дублирования записи на одну дату по связке телефона и email.

## 6. Конфигурация через .env

Все порты, параметры подключения к БД и секретные ключи настраиваются через переменные окружения или файл `.env`:

Создайте файл `.env` на основе примера `.env.example`:
```ini
# Порт сервера
SERVER_PORT=8080

# База данных PostgreSQL
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/konyaev
SPRING_DATASOURCE_USERNAME=konyaev
SPRING_DATASOURCE_PASSWORD=your_secure_password

# Секретный ключ JWT (минимум 32 символа)
SECRET_KEY=change_this_to_a_secure_jwt_secret_key_32_characters_min

# Администратор по умолчанию
ADMIN_USERNAME=admin
ADMIN_PASSWORD=your_secure_admin_password
```

Файл `.env` добавлен в `.gitignore` и никогда не попадает в репозиторий.

## 10. Шпаргалка к защите перед преподавателем

1. **В чём заключается 3-х слойная архитектура?**  
   *«Контроллеры отвечают за приём HTTP-запросов и валидацию DTO; сервисы инкапсулируют бизнес-логику (лимиты слотов, правило 24 часов, архивация, генерация Excel); репозитории управляют взаимодействием с PostgreSQL через Spring Data JPA».*
2. **Что такое OpenAPI и Swagger?**  
   *«OpenAPI — это открытая спецификация формата описания REST API, а Swagger UI — это визуальный веб-интерфейс, генерируемый библиотекой springdoc-openapi, позволяющий просматривать и тестировать эндпоинты прямо из браузера».*
3. **Как обеспечивается надёжность и отсутствие 500 ошибок?**  
   *«Используется централизованный `@RestControllerAdvice` класс `GlobalExceptionHandler`. Все потенциальные точки сбоев (переполнение числовых типов, невалидный JSON, неверный формат дат) валидируются аннотациями Jakarta Validation и оборачиваются в HTTP 400 Bad Request с информативным телом ответа».*
